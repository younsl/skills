# Web UI

## Output Requirements

### Layout

- Consoles over many entities are one drill-down (overview, environment, instance, detail) with a breadcrumb, not top tab bars or long instance pickers. Drill state lives in query params
- Minimal cards: large monospace numbers in columns split by thin lines, a thin segmented status bar, and color only for state (ok, warn, danger). No text badge that repeats the color
- Small secondary lists fold into their parent card instead of getting their own section
- Trees start collapsed with roots only, and parent rows carry aggregates (count, failures, running). Auto-expand only while a search or filter is active
- Metadata (level, period, author, updated) shows as icon and value chips, never one joined sentence

### Interaction

- No browser native dialogs (`alert`, `confirm`, `prompt`) and no `title` tooltips. Use the app's modal and tooltip components
- A control that changes one panel sits on that panel with its own state. Per-panel state goes in the URL as a compact map with defaults omitted
- A clickable card that contains controls is a `div` with `role="link"` and click and Enter handlers, and inner controls stop propagation. No nested buttons
- Copy icons appear only on hover or focus, right after the value they copy
- Search over large tables runs on the server. One input: plain text is a substring match, `/pattern/` is a case-insensitive regex with an inline error for an invalid pattern. No separate regex toggle
- Permission-gated actions render a clear denied state

### Charts

- Thresholds and reference lines are dashed, with only the steps asked for
- Resource charts use absolute units (cores, MiB, GiB). Request is an amber dashed line and limit a red dashed line with no text on the line, values in a legend below and in the tooltip. Offset the dash when request equals limit so both show
- One unit per axis, adaptive units only in tooltips

### Copy

- UI copy follows writing-style, and descriptions and help text carry no colon
- New locale keys go into every locale file in the file's existing order

### Code

- Generated files (route trees, API clients) are regenerated by their tool, never hand-edited
- Escape sequences for invisible code points (variation selectors, zero width joiners) stay backslash escapes in source. Check with `cat -v` after writing
- Portal plugins use the portal's current component library. A library the portal is migrating away from is never newly imported

## Local Verification

- After a UI change, rebuild and restart the local instance (including any binary that embeds the web bundle), then tell the operator the URL and where to click
- Read-only screens are checked against the live API. Mock mode only for write screens the local API cannot perform
- Automation never signs in through the real identity provider. Use the repo's local dev identity setting in a config copy
- Run tools from `./node_modules/.bin` directly when the package manager's run command would trigger an install

## MR Screenshots

- One capture per scenario (idle, in progress, done, result, failure) from the entry point users actually use. A shared component is captured at every entry point
- Permission-gated UI also gets a capture of the denied state
- A later commit that changes a captured screen is followed by a recapture in the same framing that replaces the old image
- Screenshots pass principle-air-gap before any public use

## Validation

- `tsc` (or `tsc -b`), `eslint` within the repo's warning cap, and the production build pass
- `grep -rnE '\b(alert|confirm|prompt)\(| title=' <changed files>` adds no new hits
- The local instance serves the new build (version endpoint or bundle hash matches)
- Every scenario in the MR has a current screenshot
